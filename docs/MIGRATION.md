## 검증 방식

- 통합 하위 폴더와 원본 루트의 Git 트리 해시 일치 여부 확인
- 모든 원본 브랜치 HEAD가 보관 브랜치에 동일한 해시로 존재하는지 확인
- 기본 브랜치 전체 커밋이 main에서 도달 가능한지 확인
- git fsck --full로 Git 객체 무결성 확인

빌드와 실행 테스트는 수행하지 않았습니다. 기존 소스 및 빌드 설정을 보존했습니다.
Windows에서 허용하지 않는 피신 파일명도 변경 없이 보존했습니다.

## 보안 정리 후 검증

- 기존 60개 커밋의 토큰 파일 외 모든 트리 항목과 메타데이터를 대조했습니다.
- 과제 폴더 5개의 현재 트리는 원본과 동일합니다.
- 정리한 모든 보관 브랜치의 커밋 수와 부모 관계를 보존했습니다.
- 토큰 파일의 이력과 토큰 blob이 통합본에서 제거되었는지 확인했습니다.
- 원본 GitHub 저장소의 기록은 변경하지 않았습니다.

[커밋 대응표](COMMIT_MAP.tsv)에서 변경 전후 해시를 확인할 수 있습니다.
